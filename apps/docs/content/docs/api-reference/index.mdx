Vaze exposes a REST API under `/api` on your instance. Anything you can do in
the dashboard, you can do over HTTP from any language.

```
https://<your-vaze-instance>/api
```

## Authentication

Create an API key from the **API Keys** page in the dashboard, then send it
in the `API-Key` header on every request:

```bash
curl https://files.example.com/api/files \
  -H "API-Key: your-api-key"
```

Requests without a valid key receive a `401` response:

```json
{ "data": null, "error": { "message": "Unauthorized" } }
```

A key acts as the user who created it, with that user's current role. If the
role doesn't grant what an endpoint needs, the request receives a `403` that
names the missing [scope](#scopes):

```json
{ "data": null, "error": { "message": "Missing required scope \"files:write\"" } }
```

<Callout>
  The only endpoints that skip authentication are the [health
  check](#health-check) and the public [file hosting
  endpoint](/docs/api-reference/files#serve-a-file-publicly).
</Callout>

## Response envelope

Every JSON endpoint responds with the same envelope:

```json
// success
{ "data": { ... }, "error": null }

// failure
{ "data": null, "error": { "message": "File not found" } }
```

Errors also carry a meaningful HTTP status code:

| Status | Meaning                                                     |
| ------ | ----------------------------------------------------------- |
| `400`  | Invalid input (missing fields, invalid names)               |
| `401`  | Missing or invalid API key, or its owner is disabled        |
| `403`  | The key's owner lacks the scope the endpoint needs          |
| `404`  | File or folder not found                                    |
| `409`  | Name conflict (a name already taken in the same folder)     |
| `413`  | Upload too large, or too many files in one request          |
| `429`  | Rate limited — retry after the `Retry-After` header         |
| `500`  | Unexpected server error                                     |
| `507`  | Not enough free space on the volume                         |

## Scopes

An admin gives every user a role on the **Users** page of the dashboard. Each
role is a set of scopes, and the **Custom** role lets the admin pick scopes one
by one:

| Scope             | Admin | Editor | Viewer | Grants                                                       |
| ----------------- | ----- | ------ | ------ | ------------------------------------------------------------ |
| `files:read`      | ✓     | ✓      | ✓      | List, search, download and sign files; browse and zip folders |
| `files:write`     | ✓     | ✓      |        | Upload, rename and change visibility; create and rename folders |
| `files:delete`    | ✓     | ✓      |        | Delete files and folders                                      |
| `api-keys:manage` | ✓     | ✓      |        | Create API keys, and call the API with them                   |
| `settings:manage` | ✓     |        |        | Instance settings (dashboard only)                            |
| `users:manage`    | ✓     |        |        | Add, edit, disable and remove users (dashboard only; Admin role only) |

`api-keys:manage` is checked on every request made with a key, so taking it
away (or disabling the user) stops all of that user's keys at once. Role
changes apply to the very next request.

| Endpoint                                                | Scope          |
| ------------------------------------------------------- | -------------- |
| `GET /api/files`, `GET /api/folders`                    | `files:read`   |
| `GET /api/files/download/:id`, `POST /api/files/download` | `files:read` |
| `GET /api/folders/download`, `POST /api/files/sign`     | `files:read`   |
| Private files on `GET /api/hosting/...` (with a key)    | `files:read`   |
| `POST /api/files`, `PUT /api/files`                     | `files:write`  |
| `POST /api/folders`, `PUT /api/folders`                 | `files:write`  |
| `DELETE /api/files`, `DELETE /api/folders`              | `files:delete` |

## Rate limits

Requests are limited per client IP: 300/minute across `/api`, and 600/minute
on the public hosting endpoint. Exceeding either responds `429`.

## List query parameters

Endpoints that return lists of files accept these query parameters:

| Parameter        | Default     | Description                                     |
| ---------------- | ----------- | ----------------------------------------------- |
| `limit`          | unlimited   | Maximum number of files to return               |
| `offset`         | `0`         | Number of files to skip (for pagination)        |
| `orderBy`        | `createdAt` | One of `createdAt`, `updatedAt`, `name`, `size` |
| `orderDirection` | `DESC`      | `ASC` or `DESC`                                 |

## Health check

`GET /api/health` — no authentication required. Useful for uptime monitoring
and container health checks:

```json
{ "data": { "message": "Vaze is running!" }, "error": null }
```
