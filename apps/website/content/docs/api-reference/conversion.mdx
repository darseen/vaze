title: Conversion
description: Extract the audio of a video as an MP3, and convert and resize images

---

Conversion runs on the server: ffmpeg for video, and libvips and libheif for
images, all of which the Docker image includes. The result comes back as the
response and is not stored, so save it, or
[upload](/docs/api-reference/files#upload-files) it, if you want to keep it.

Converting needs the `files:read` scope. It works with an [`API-Key`
header](/docs/api-reference#authentication) or a signed-in session.

## Video to audio

```
POST /api/conversion/video-to-audio
```

Send a stored file by its id as JSON:

```json
{ "fileId": "<id>" }
```

Or send a file from your device as `multipart/form-data`, with one file part.
It is stored only until the conversion ends, and may be as large as
`maxUploadSize` under [instance settings](/docs/api-reference/settings).

```bash
curl -X POST https://vaze.example.com/api/conversion/video-to-audio \
  -H "API-Key: $VAZE_API_KEY" \
  -F "file=@clip.mp4" \
  -o clip.mp3
```

The response is the MP3 itself, with `Content-Type: audio/mpeg` and a
`Content-Disposition` naming it after the video, e.g. `clip.mp3`. Audio is
192 kbps constant bitrate, from the video's main audio track.

The audio streams back while it is converted, so the response has no
`Content-Length`. When the video declares its length, `X-Content-Duration`
gives it in seconds, and the final size is about `duration × 24000` bytes, which
is enough to show progress. Closing the connection stops the conversion.

MP4, MOV, MKV, WebM, AVI, FLV, MPEG-TS, MPEG and WMV videos are supported, and
so are MP3, WAV, FLAC, AAC and Ogg audio files.

| Status | Meaning                                                                  |
| ------ | ------------------------------------------------------------------------ |
| `400`  | No `fileId`, or a form with more than one file                           |
| `404`  | No file with that id                                                     |
| `413`  | The uploaded file is larger than `maxUploadSize`                         |
| `422`  | The video has no audio track, or is not a format that can be read        |
| `503`  | The server is busy with other conversions; retry after `Retry-After`     |
| `507`  | Not enough free space on the volume to hold the uploaded file meanwhile  |

The errors use the usual [response envelope](/docs/api-reference#response-envelope).
The server runs a few video conversions at a time, depending on its CPU cores,
and each client may start 30 per minute.

## Images

```
POST /api/conversion/image
```

Converts an image to WebP, JPG, PNG or AVIF, and resizes it if you ask. Needs
Vaze 4.6.0 or later. Send a stored file by its id as JSON, with the options
beside it:

```json
{ "fileId": "<id>", "format": "webp", "quality": 80, "width": 1920, "height": 1920 }
```

Or send a file from your device as `multipart/form-data`, with the options as
fields and one file part. It is stored only until the conversion ends, and may
be as large as `maxUploadSize`.

```bash
curl -X POST https://vaze.example.com/api/conversion/image \
  -H "API-Key: $VAZE_API_KEY" \
  -F "format=webp" \
  -F "width=1920" \
  -F "height=1920" \
  -F "file=@photo.heic" \
  -o photo.webp
```

| Option            | Description                                                                                                                                  |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `format`          | Required. `webp`, `jpeg` (or `jpg`), `png` or `avif`                                                                                         |
| `quality`         | 1 to 100. Defaults to 80, or 50 for AVIF, which looks as good at a lower number. PNG is lossless and ignores it                              |
| `width`, `height` | Up to 16384 each. The image is fitted inside this box, keeping its shape, and never made larger than it is. Give one to limit only that side |

The response is the image itself, with its `Content-Type`, a
`Content-Length`, and a `Content-Disposition` naming it after the original,
e.g. `photo.webp`. `X-Image-Width` and `X-Image-Height` give its size in
pixels.

Every image comes out upright and in sRGB, without metadata such as the camera,
when it was taken or where. An animated GIF or WebP stays animated as WebP,
while the other formats take its first frame. JPG has no transparency, so
transparent areas turn white. SVGs are drawn at the size asked for, so they
stay sharp when made larger.

JPEG, PNG, WebP, AVIF, GIF, TIFF, SVG and HEIC images can be converted,
including the HEIC photos phones take.

| Status | Meaning                                                                         |
| ------ | ------------------------------------------------------------------------------- |
| `400`  | No `fileId`, an option that isn't valid, or a form with more than one file      |
| `404`  | No file with that id                                                            |
| `413`  | The uploaded file is larger than `maxUploadSize`                                |
| `422`  | Not an image that can be read, a damaged one, or too large for the format       |
| `503`  | Too many images are waiting to be converted; retry after `Retry-After`          |
| `507`  | Not enough free space on the volume to hold the uploaded file meanwhile         |

The server converts one image at a time and lets a few more wait their turn,
so a handful of requests at once all succeed. Each client may start 60 per
minute.
